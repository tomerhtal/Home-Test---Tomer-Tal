## איך מריצים

דרישות: [.NET 8 SDK ומעלה](https://dotnet.microsoft.com/download/dotnet/8.0). ברירת המחדל היא מודל מדומה (Mock), ולכן לא צריך חשבון AWS.

פותחים חלון פקודות **בתיקייה הראשית של הפרויקט** (התיקייה שבה נמצא `README.md`) ומריצים:

<div dir="ltr">

```bash
# API + UI: then open http://localhost:5080 in the browser (stop: Ctrl+C)
dotnet run --project src/PortfolioAssistant.Api

# Eval: 14 cases, score and GO / NO-GO
dotnet run --project eval/PortfolioAssistant.Eval -- --verbose

# Unit tests
dotnet test tests/PortfolioAssistant.Tests
```

</div>

ב-Windows אפשר לפתוח חלון פקודות בתיקייה כך: בשורת הכתובת של סייר הקבצים מקלידים `cmd` ולוחצים Enter.

**הרצה בלי התקנה (GitHub Codespaces):** בעמוד המאגר לוחצים **Code** ← **Codespaces** ← **Create codespace on main**. אחרי כדקה נפתח עורך בדפדפן עם טרמינל, ושם מריצים את אותן פקודות. כשה-API עולה, מופיע כפתור **Open in Browser** לפורט 5080.

**פתרון בעיות:** אם הבנייה נכשלת בגלל חבילת ה-AWS SDK (אין גישה ל-NuGet, או ש-Windows חוסם קובץ ממנה), אפשר לבנות את ה-API בלעדיה, כי המודל המדומה לא צריך אותה:

אם Windows חוסם את ההרצה עם הודעה על Application Control ("בקרת אפליקציות חכמה"), זו מדיניות אבטחה של המחשב ולא בעיה בפרויקט. במקרה כזה אפשר להריץ ב-Codespaces.

<div dir="ltr">

```bash
dotnet run --project src/PortfolioAssistant.Api -p:IncludeBedrock=false
```

</div>

**נקודת הכניסה:** `POST /api/ask` עם `{ "customerId": "C-1042", "question": "..." }` והכותרת `X-User-Id` (במקום SSO).
ב-UI בוחרים משתמש (pm-317 משויך ל-C-1042, pm-402 משויך ל-C-3000), לקוח ושאלה. ברשימה בצד יש את כל שאלות התרגיל: לחיצה על שאלה מעתיקה אותה לשורת השליחה, והשליחה בכפתור.

<div dir="ltr">

```bash
curl -X POST http://localhost:5080/api/ask -H "Content-Type: application/json" -H "X-User-Id: pm-317" \
     -d '{"customerId":"C-1042","question":"מה השווי הנוכחי של התיק של C-1042?"}'
```

</div>

**מעבר למודל אמיתי:** ב-`src/PortfolioAssistant.Api/appsettings.json` משנים את `Llm:Provider` ל-`Bedrock`, ממלאים את מזהי המודלים והאזור. נדרשות הרשאות AWS לגישה ל-Bedrock.

## החלטות מרכזיות

- **‎.NET ולא Python.** הסביבה הקיימת והצוות הם ‎.NET. העבודה מול המודל היא קריאות API, ואין סיבה להוסיף שפה שנייה לתחזוקה.
- **מודל מדומה כברירת מחדל.** כך הפרויקט רץ אצל כל אחד בלי מפתחות, וה-eval דטרמיניסטי. ה-Mock מחליף רק את "המוח" (איזה כלי לבקש וניסוח לפי תבנית). הלולאה, הכלים, החישובים, ההרשאות, החיפוש, הבדיקות והלוג רצים באמת. המתאם ל-Bedrock מממש את אותו ממשק.
- **כל מספר מחושב בקוד.** הכלים מחזירים תוצאה סופית ומעוצבת (`decimal`, עיגול אחד בסוף). `OutputGuard` חוסם תשובה עם מספר שלא הגיע מכלי, כולל עיגול של המודל (51.2 במקום 51.24).
- **ערכי המדיניות מגיעים מהמסמכים עצמם.** 60% ו-0.8% שמורים כשדות `rule.*` במטא-דאטה של מסמכי המדיניות, באותו קובץ ובאותה גרסה כמו הטקסט. בדיקת יחידה מוודאת שהערך תואם לטקסט.
- **הרשאות נאכפות בגישה לנתונים, לא במודל.** `UserContext` מגיע מהכותרת (בייצור מה-token) ולא מארגומנט שהמודל ממלא. לקוח שלא קיים ולקוח של מנהל אחר מקבלים אותה תשובה. סינון ה-audience במסמכים קורה לפני הדירוג.
- **חיפוש מילות מפתח במקום embeddings.** ארבעה מסמכים קצרים לא מצדיקים vector store. החיפוש מטפל בתחיליות בעברית ("בסקירת השוק" ל"סקירת שוק") ונבדק. מאחורי `IDocumentStore`, כך שבייצור מחליפים במימוש מעל Bedrock Knowledge Bases.
- **ייעוץ ו-injection נחסמים לפני המודל**, בסירוב מנוסח מראש (`Guards/Messages.cs`). בפלט נבדק ייעוץ עקיף שהמודל הוסיף לשאלה תמימה; ציטוט של מדיניות הייעוץ עצמה לא נחשב ייעוץ.
- **Fail-closed.** תשובה שנכשלה פעמיים בבדיקת הפלט לא מוצגת. מודל ראשי שנפל מוחלף במודל גיבוי, ואם גם הוא לא זמין, מוצגת הודעה מסודרת.
- **הנחות:** שווי התיק הדיגיטלי כולל מטבעות יציבים; דמי ניהול רבעוניים = שיעור שנתי חלקי 4 על השווי הנוכחי; "לא יעלה על 60%" פירושו שבדיוק 60% מותר.

## מה חסר כדי להגיע לייצור

- **מודל אמיתי:** הרצת ה-eval מול Bedrock והרחבת ה-eval set לכ-100 שאלות, מסומנות על ידי הציות. `BedrockLlmClient` נכתב לפי ה-API של Bedrock **ולא נבדק מול השירות**.
- **זהות:** אימות token של ה-SSO הארגוני במקום הכותרת `X-User-Id`.
- **מערכות מקור:** מאגר תיקים מול ה-API או ה-DB האמיתי (JOIN על טבלת השיוך, משתמש לקריאה בלבד) ומקור השערים של הפלטפורמה עם cache ובדיקת שער ישן (קיימת בקוד, כבויה באב-טיפוס כי הקובץ סטטי).
- **RAG:** Bedrock Knowledge Bases עם מסמכים ב-S3, מטא-דאטה, סנכרון אוטומטי ותהליך אישור למסמכים.
- **Guardrails:** Bedrock Guardrails בקלט ובפלט (נושא אסור, prompt attack, PII, grounding), מודל שופט לייעוץ עקיף, ובדיקת injection על תוצאות החיפוש.
- **תפעול:** לוגים ל-CloudWatch עם הרשאות מוגבלות, מטריקות עלות וזמן תגובה, circuit breaker (Polly), הגבלת קצב, Prompt Caching ו-Secrets Manager.
- **CI:** הרצת הבדיקות וה-eval בכל שינוי, כשער לעלייה לאוויר.
